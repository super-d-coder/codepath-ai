## 推荐阅读顺序

### 新 Agent / 新开发任务

1. 阅读 `01-项目规范与架构约束.md`，确认模块边界和依赖方向；
2. 阅读任务领域的开发计划，例如 `02-InfoFlow-MVP开发计划.md`；
3. 阅读该领域的开发情况，例如 `infoflow/01-InfoFlow-MVP开发情况.md`；
4. 阅读对应 SQL，确认表结构、索引与去重策略；
5. 修改代码后更新开发情况，并执行文档记录的验证命令。

### 部署或联调 InfoFlow

1. 执行 `sql/infoflow.sql`；
2. 在 `application-local.yml` 配置本地数据库；
3. 可选设置环境变量 `GITHUB_TOKEN`；
4. 启动应用并调用 InfoFlow 手动采集接口；
5. 查询数据库和 GET 接口，记录验收结果。

## 文档维护原则

- **计划不覆盖事实**：`02-InfoFlow-MVP开发计划.md` 保留为范围与设计基线；实际实现、偏差和验证结果写入领域开发情况文件。
- **代码和文档同一提交维护**：涉及接口、表结构、配置、依赖、调度表达式或运行方式的改动，必须同步更新相应开发情况文件。
- **不记录敏感信息**：数据库密码、Token、私钥、服务器地址等只能写配置项名称和注入方式，不能写真实值。
- **可验证优先**：文档中的“已完成”必须附带已执行的构建、测试、接口或数据库验证范围；未实际验证的项目必须标注为“待验收”。
- **单一事实源**：架构约束写在 `01`，领域计划写在 `02`，领域当前状态写在 `infoflow/`；不要在 README 或多个文档复制维护同一份详细状态。
